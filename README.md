# WordPress LDAP login wp fork

Расширенная версия бесплатной версии плагина [WordPress LDAP Login for Intranet Sites](https://plugins.miniorange.com/wordpress-ldap-login-intranet-sites) с поддержкой дополнительных полей пользователя и поддержкой интеграции с ALD Pro

## ✨ Особенности форка

Вырезаны "платные" не заполняемые поля
Добавлены атрибутов LDAP:
- **Фамилия**
- **Имя**
- **Отчество** 
- **Должность**
- **Фотография профиля** — синхронизация аватара WordPress и wpForo при LDAP-входе.

## 🛠 Установка

1. Скачайте репозиторий
2. В админ-панели WordPress:
   - Перейдите в `Плагины → Добавить новый`
   - Нажмите `Загрузить плагин`
   - Выберите скачанный ZIP-файл
3. Активируйте плагин

## ⚙ Настройка
После активации, в настройках плагина появятся новые поля

### Фотография из AD / ALD Pro для wpForo

В разделе **Attribute Mapping** добавлено поле **«Фотография профиля»**:

- Пустое поле включает автоматический поиск: сначала `thumbnailPhoto`, затем `jpegPhoto`.
- Для явного выбора укажите `thumbnailPhoto` (AD), `jpegPhoto` или другое имя атрибута вашей схемы. Поддерживается суффикс `;binary`.
- Атрибут должен содержать бинарное изображение JPEG, PNG или GIF. Ссылки на фотографии и текст base64 не используются. Ограничения: до 5 МиБ, не более 4096 пикселей по стороне и 16 миллионов пикселей всего.

Служебной учётной записи LDAP нужно право чтения атрибута фотографии. Фото должно быть заполнено в самом каталоге.

Фотография загружается при **успешном LDAP-входе**, в том числе при автоматическом создании пользователя. Уже зарегистрированным пользователям достаточно выйти и войти снова через LDAP. Массовой загрузки без входа пользователя нет.

Плагин сохраняет фото в стандартной папке загрузок WordPress и использует его как аватар через фильтры WordPress и wpForo. Для wpForo проверены точки интеграции в исходниках версий [2.4.17](https://downloads.wordpress.org/plugin/wpforo.2.4.17.zip) и [3.2.5](https://downloads.wordpress.org/plugin/wpforo.3.2.5.zip). Фото LDAP имеет приоритет над аватаром, выбранным в wpForo. Исходный аватар wpForo сохраняется в настройках форума.

Редактор аватара в настройках аккаунта wpForo продолжает показывать его собственный ручной выбор. При наличии LDAP-фото профиль, сообщения и список участников показывают фотографию из каталога. Если аватар уже выводился до синхронизации в рамках того же HTTP-запроса, wpForo может удерживать старое изображение в памяти до следующего запроса; обычное перенаправление после входа обновляет его.

Одинаковое фото повторно не записывается. При изменении фотографии создаётся новый URL, а предыдущий файл, созданный этим плагином, удаляется. Если фото отсутствует, недоступно для чтения, имеет неподдерживаемый формат или его не удалось сохранить, вход продолжается и прежний аватар остаётся. Удаление фотографии в каталоге само по себе не удаляет ранее загруженный аватар. При удалении пользователя WordPress его файл фотографии очищается.

### Проверка доработки

Локальные проверки без WordPress и LDAP-сервера:

```sh
php tests/run.php
```

Дополнительная проверка на настоящих методах локального wpForo:

```sh
php tests/wpforo-integration.php
```

По умолчанию исходники читаются из `wp-foro/`. Для другой папки передайте её путь первым аргументом. Тест использует настоящие методы wpForo с заглушками WordPress, БД и кеша, не меняет исходники форума и не заменяет проверку на работающем сайте. Папка `wp-foro/` исключена из Git; тесты и исходники форума не входят в установочный ZIP LDAP-плагина.

Для проверки на вашем сервере войдите через LDAP пользователем с фотографией и откройте его профиль и сообщение в wpForo. Затем измените фотографию в каталоге и войдите повторно: аватар должен обновиться. Проверьте также пользователя без фотографии и неверный пароль. Каталог загрузок WordPress должен быть доступен для записи.
